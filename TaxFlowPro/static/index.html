TaxFlow Pro — Help Guide
Quick start: (1) Add or select a client in Client Management, setting their Financial Year if you plan to use the portal downloader → (2) Get returns in — either Upload Returns with GSTR-1/GSTR-2B JSON or ZIP files, or use Download GSTR-2B from Portal to fetch Purchases directly → (3) Go to TallyPrime XML Export, generate the XML, and either download it for manual import or push it straight to a running TallyPrime instance.

  • Click Add New Client and enter the taxpayer's GSTIN, name, and (optionally) their GST portal login and Financial Year. PAN and State are auto-derived from the GSTIN.
  • The Financial Year field only matters for the portal downloader (below) — it scopes which months you're allowed to fetch for that client. Manual JSON/ZIP uploads aren't restricted by it, since a return filed late can legitimately carry invoices from a prior year.
  • The saved GST Username/Password auto-fills both the Counterparties portal-verification login and the GSTR-2B portal downloader login — you only ever have to type the CAPTCHA shown on this page.
  • Click a client card's Select Taxpayer to make it the active client — every other tab then works only on that client's data.
  • Each card shows the actual calendar months present in that client's Sales and Purchases data separately, derived from the invoice dates themselves — not from filenames — so it stays accurate regardless of what the uploaded files were named.
  • Use Upload Returns to ingest a GSTR-1 or GSTR-2B JSON/ZIP file — the return type (Sales vs Purchases) is auto-detected per file, so one batch can mix both. Only the extracted invoice data is stored; raw uploaded files are parsed once in memory and never written to disk.
  • If an uploaded file's GSTIN doesn't match the active client, or its period already has data loaded, the app stops and asks you to confirm before doing anything — it never silently switches clients, creates a duplicate client, or piles duplicate data into a period behind your back.

Use the Sales (GSTR-1) / Purchases (GSTR-2B) toggle at the top to switch which side of the ledger you're viewing — they're tracked as two completely separate datasets for the same client. One row per uploaded return period, with a document-type breakdown and tax totals:

Sales (GSTR-1) — 5 categories: B2B, B2C (small consolidated + single large interstate invoices >₹2.5L), CDNR (credit/debit notes), EXP (zero-rated exports), ADV (tax on advances received, and its later adjustment).

Purchases (GSTR-2B) — 4 categories: B2B, RCM (reverse-charge, self-assessed), CDNR, and Ineligible (ITC that GSTN itself flags as not claimable). Purchases has one fewer category than Sales, so its table is one column narrower — that's expected, not a missing column.

Click any column header to sort by it, and the table header stays pinned while you scroll a long list.

Use on a row to delete just that period, or Clear Returns to wipe every period of the currently selected type for the client. Either one also tries to cancel any vouchers that period had already pushed into Tally (see section 6) — if Tally isn't reachable at that moment, it tells you plainly so you can cancel them there yourself.

  • Lists every distinct GSTIN found across the client's invoices — from both Sales and Purchases at once — with the Trade/Legal name that will be used for its Tally ledger.
  • The All / Sales / Purchases toggle filters the list by which side a GSTIN appears on. A GSTIN that's both a customer and a supplier (tagged "Customer & Supplier") stays visible under either toggle, not just one.
  • Verify Portal launches an automated, headless lookup against the official GST portal to fetch the real registered Trade Name, Legal Name, and status for each GSTIN. You'll be asked to solve one CAPTCHA per login attempt, shown right on this page; verified names are saved permanently and reused on every future export.
  • You can also manually edit a party's Trade/Legal name at any time — manual edits are saved permanently and take priority.
  • The Trade Name / Legal Name toggle (in the top toolbar) switches which name is used to build every ledger across the whole app.

  • Every normalized document behind the summary numbers — searchable by invoice number, GSTIN, or party name, filterable by type and balance status, and sortable by clicking any column header.
  • Tax is broken out into separate CGST / SGST / IGST columns rather than one lumped "GST" figure, so you can see exactly which duty ledger each rupee belongs to.
  • The Rate column shows the true total GST rate charged (e.g. 18%, not 9%) — it's computed by doubling the CGST-side rate for intrastate invoices, since CGST and SGST are each stored at half the real rate. If a single invoice mixes line items at different rates, it honestly shows "Multiple (5%, 18%)" instead of picking one and hiding the rest. "Nil-Rated" means this specific document carries no tax of its own — most commonly a reverse-charge purchase, where the tax lives on its separate RCM self-invoice journal row instead.
  • A reverse-charge purchase always shows as two linked rows — the purchase itself (at taxable value only) and its RCM self-invoice journal (the self-assessed tax). Both together are what reaches Tally.
  • Export to Excel downloads every row matching your current search/filter/sort — not just the visible page — as a formatted .xlsx file with the same CGST/SGST/IGST/Rate breakdown shown on screen.
  • Use the Rows selector and Go to box next to the pagination to change page size or jump straight to a page on a large list.

  • An alternative to manually downloading GSTR-2B from the GST portal yourself and uploading it — this launches a headless Chrome session that logs in with the client's saved GST credentials, navigates the Returns Dashboard, and pulls GSTR-2B JSON for whichever months you tick.
  • Months are restricted to the client's configured Financial Year — set it on the client's profile first if you haven't (see section 1).
  • Login needs one CAPTCHA, shown right on this page the same way portal verification does; type what you see and submit to continue.
  • A month with genuinely no GSTR-2B data available is reported as such and skipped — that's not an error, just nothing to fetch yet for that period.
  • Downloaded files are never saved to disk — each one is parsed in memory, its extracted documents are stored, and the file is deleted immediately, the same no-storage policy as manual uploads.

  1. The Sales (GSTR-1) / Purchases (GSTR-2B) toggle picks which dataset to export — each generates its own pair of files (Consolidated_Masters_Sales.xml/Consolidated_Entries_Sales.xml or the _Purchases equivalents), so generating one never overwrites the other. They're always pushed to Tally separately, never combined into one payload.
  2. Method 1 — Generate Consolidated XML builds the Masters file (ledgers to create) and Entries file (vouchers to post) for whichever side is currently selected. Any document whose total doesn't reconcile with its taxable value + tax by more than ₹2 is excluded from the Entries file and counted separately, rather than pushed in as bad data.
  3. Download the files for manual import via Tally's Import Data menu, or use Method 2 — Live TallyPrime HTTP Direct Import to POST them straight to a running TallyPrime instance over HTTP. It requires Tally's HTTP server enabled on port 9000 (Gateway of Tally → F1 Help → Settings → Connectivity) — the status pill in the top-right shows whether it's currently reachable.
  4. Always import Masters before Entries — vouchers reference ledgers that must already exist in the company. "Full Live Import" does this in the correct order automatically.
  5. Every push is regenerated fresh from what's currently in the app first, so it always reflects exactly what you can see on screen — never stale or already-deleted data.
  6. Because the whole consolidated file is resent every time, vouchers already in Tally from a previous push will show as Altered again on a re-push, not just newly-added ones as Created — that's expected given the all-in-one-file design, not a sign of duplication.
  7. If Tally accepts the connection but reports errors or exceptions for individual vouchers, the result is shown as "Completed with Issues" rather than a blanket success, with the per-file created/altered/error counts underneath.
  8. Deleting a period or clearing returns (section 2) will also try to cancel, in Tally, any vouchers that period previously pushed there — keeping this tool and Tally in sync instead of leaving orphaned vouchers behind.

  • "Cannot connect to TallyPrime" — Tally isn't running, the company isn't open, or the HTTP server / port 9000 isn't enabled. Click the status pill to re-check.
  • Upload asks to confirm a GSTIN mismatch — the file you're uploading belongs to a different GSTIN than the currently active client. Confirming either switches to (or creates) the client that GSTIN actually belongs to; cancelling leaves your active client and its data untouched.
  • Upload asks to confirm duplicate periods — the file's period already has data loaded for this client. Confirming adds to what's already there; tick Clear Existing beforehand instead if you want a clean replace.
  • Rate column shows "Multiple (...)" — that invoice genuinely has line items at more than one GST rate; the CGST/SGST/IGST amount columns are still summed correctly across all of them regardless.
  • Rate column shows "Nil-Rated" — this specific document has no tax lines of its own; check for a linked row (same document number, different type) carrying the actual tax, most commonly an RCM self-invoice.
  • Zero-value invoices are intentionally excluded from the XML — they carry no accounting entry.
  • GST portal login (verification or GSTR-2B download) stuck on a CAPTCHA — you have 5 minutes to type the answer shown; it retries automatically up to 3 times on a wrong answer before failing.
  • Ineligible-ITC purchases post at their full invoice value with no separate tax ledger line, since the tax isn't recoverable and is treated as part of the cost.
  • All data lives in one local file — client_memory.db. There is currently no built-in backup/export for it, so back that file up yourself periodically if you want protection against accidental data loss.
  • ISD credit distribution and import-of-goods (Bill of Entry) sections of GSTR-2B are not yet supported.
All processing is local — no invoice data ever leaves this machine except to your own Tally instance or the official GST portal.
